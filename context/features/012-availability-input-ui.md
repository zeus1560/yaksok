# 가능 시간 입력 화면 (내 시간 입력·모두의 시간·폴링 동기화)

## 식별자와 상태

- 스펙 ID: `012-availability-input-ui`
- 상태: 완료
- 문서 작성만으로 구현이나 검증을 완료 처리하지 않는다.

## 근거

- 비즈니스 규칙: TIME-01-01(서울 기준), TIME-05-02(24:00), TIME-06-01(30분 슬롯), TIME-08-01(지난 슬롯), TIME-09-01(날짜 단위 선택), TIME-10-02(제출 의미, 로컬 키 = 약속ID + 참여자ID), TIME-10-03, TIME-10-04(임시 저장·버전 동기화·5초 폴링·SWR), TIME-11-01·11-02(제출 후 수정 표시), TIME-12-01(빈 선택 확인), TIME-12-02(가능/불가능 두 가지, 분모 = 전체 참여자), TIME-15-01~04(서버 시각 마감), STATE-06-02(마감 후 본인 입력 확인)
- API: TIME-API-01·02 (`docs/specs/api/time.md`), MEMBER-API-05(도착 화면 진입)
- 관련 미결·충돌: TIME-09-03·09-04(큰 블록 일부 선택, ❗미결 — 큰 블록 선택은 만들지 않음), TIME-10-01(저장 시점, 본문은 TIME-10-04 참조 — TIME-10-04대로 구현), R-14(코드 정렬). 이번 결정은 R-19

## 사용자와 문제

참여(또는 방장 등록)를 마친 사람이 도착 화면에서 자기 가능 시간을 고르고 제출하며, 다른 참여자의 제출 현황을 칸별 인원으로 본다. 여러 기기에서 같은 참여자가 입력해도 서로의 제출을 덮어쓰지 않아야 한다.

## 목표와 범위

- 이번에 구현할 동작:
  - 내 가능 시간 그리드(열 = 한국 날짜, 행 = 30분 칸)와 제출(TIME-API-01)
  - 모두의 가능 시간(TIME-API-02, 읽기 전용): 칸별 가능 인원 색 농도, 칸 선택 시 가능한 사람 이름
  - 마감까지 남은 시간(서버 시각 기준), 제출 상태(제출 전·제출됨·수정 중)
  - 5초 폴링(SWR), 탭 숨김 시 중지·복귀 시 즉시 조회, 드래그·제출 중 반영 보류, 다른 기기 변경 동기화
  - 상태별 처리: closed·confirmed 읽기 전용, draft·cancelled·401 등은 링크 재조회(011 흐름)
  - 실패 분기 순수 함수(에러 코드 기준)와 코드별 테스트
  - 완료 화면(009)의 "내 가능 시간 입력하기"를 활성화해 입력 화면으로 연결
- 이번에 구현하지 않을 동작: 추천 시간·확정·마감 연장·조기 마감·탈퇴 등 STATE/RESULT 기능, 큰 시간 블록 선택(TIME-09-02, 일부 선택 표시 미결), 레이트 리밋, ETag, API·DB 변경

## 선행 작업

- 011 — 도착 화면과 링크 재조회 흐름(`invite-flow.tsx`)
- 007·008 — TIME-API-01·02

## 사용자 흐름

1. 링크 진입 → `/me` 200(collecting·closed·confirmed) → 도착 화면 = 가능 시간 화면
2. 첫 조회 전 "가능 시간을 불러오고 있어요", 로컬 임시 입력이 있으면 첫 조회 결과와 버전을 비교해 유지·폐기
3. 칸 선택 → 로컬 저장 `{ v: 1, baseVersion, slots }`(키 `yaksok:availability:{promiseId}:{participantId}`) → "수정 중" 표시
4. 제출 → 200: 로컬 삭제, "제출됨", 범위 밖 제외 안내 / 409 충돌: details로 다시 그림 / `VOTING_CLOSED`: 읽기 전용 / 나머지: 에러 코드 분기
5. 폴링 5초: 모두의 시간 갱신, 내 버전이 달라졌으면 로컬 폐기 + "다른 곳에서 내용이 바뀌었어요"

## 수용 기준

- [x] AC-1 (TIME-06-01, TIME-05-02, TIME-01-01): 칸은 시작 ≥ 하루 시작, 시작 + 30분 ≤ 하루 종료(24:00 = 1440)만 그린다. 날짜·시각 계산은 기기 시간대와 무관(TZ=UTC·America/Los_Angeles에서도 테스트 통과)
- [x] AC-2 (TIME-08-01, TIME-15-03): 지난 칸 판정과 남은 시간은 `serverTime` + 받은 뒤 경과 시간 기준. 지난 칸은 회색·변경 불가. 서버 슬롯은 시각 값으로 비교(`.000` 포함)
- [x] AC-3 (TIME-10-04): 데스크톱 드래그로 사각형 범위를 첫 칸의 반대 상태로 통일. 390px에서는 탭 선택 + 날짜 머리글 하루 전체 토글(TIME-09-01)이며 페이지·그리드 스크롤을 막지 않는다. 그리드 영역만 가로 스크롤, 시각 열 고정
- [x] AC-4 (TIME-10-02·10-04): 제출 전 입력은 로컬 `{ v: 1, baseVersion, slots }`, 새로고침 복원, 제출 성공 시 삭제
- [x] AC-5 (TIME-10-04): 폴링 `me.version` ≠ 로컬 baseVersion → 로컬 폐기·안내·`me.slots`로 다시 그림. 같으면 로컬 유지, 모두의 시간만 갱신. 409 충돌은 다시 조회하지 않고 details로 그림
- [x] AC-6 (TIME-11-02, TIME-12-01): 제출 후 "제출됨", 다시 바꾸면 "수정 중, 다시 제출 필요". 빈 선택 제출 전 확인 1회. `droppedSlotCount ≥ 1` 안내. 제출 중 버튼 비활성
- [x] AC-7 (TIME-12-02): 모두의 시간은 제출값만으로 칸별 인원/전체 참여자 색 농도, 칸 선택 시 가능한 사람 이름
- [x] AC-8 (TIME-10-04): 5초 폴링, 탭 숨김 중지·복귀 즉시 조회, 마감 뒤에도 폴링, 드래그 중 다시 그리지 않음
- [x] AC-9 (STATE-06-02, TIME-15): closed·confirmed(`VOTING_CLOSED` 포함) 읽기 전용 + 마감 안내, 미제출 로컬 입력이 있었으면 저장되지 않았음을 안내하고 지움
- [x] AC-10: draft·cancelled·401·403·404는 링크 재조회 후 그 결과 화면. 실패 분기는 에러 코드 기준 순수 함수, 코드별 테스트
- [x] AC-11: 응답 유실 후 같은 요청 재시도 → 200 정상 처리(폴링이 먼저 오면 같은 내용이므로 조용히 반영)

## 모바일 선택 방식 (결정)

- 터치(손가락·펜)는 **탭으로 한 칸씩 켜고 끄기** + **날짜 머리글 탭으로 그날 전체 켜기/끄기**(TIME-09-01: 일부 선택 → 전체 선택, 전체 선택 → 전체 해제). 마우스만 드래그 선택.
- 이유: 터치 드래그 선택은 그리드에 `touch-action: none`이 필요하고, 390px에서는 그리드가 화면 대부분을 차지해 세로·가로 스크롤이 막힌다. 길게 눌러 드래그는 발견하기 어렵고 iOS 길게 누르기 메뉴·텍스트 선택과 겹친다. 탭은 브라우저 기본 스크롤과 충돌하지 않는다(스크롤로 끝난 터치는 click이 생기지 않음). 연속 범위는 하루 전체 토글로 줄인다.
- Figma(시간 입력 화면)는 이번 작업 환경에서 열 수 없어(커넥터 미인증) 기존 Figma 토큰(`app/globals.css`)과 공통 UI로 맞췄다.
