# 휴대폰 드래그 선택

## 식별자와 상태

- 스펙 ID: `033-mobile-drag-select`
- 상태: 검토 중 — 구현·로컬 검증·미리보기 `@smoke` 2회 완료(AC-1~8). 남은 것: 안드로이드 실기기 MOBILE_CHECKLIST 10절(사용자 확인), 아이폰 Safari(공개 배포 전 팀원)

## 근거

- 비즈니스 규칙: TIME-09-01(날짜 단위 선택), TIME-10-04(드래그 중 폴링 반영 보류) — `docs/specs/rules/TIME.md`

## 사용자와 문제

휴대폰 사용자는 칸을 하나씩 눌러야 해서 여러 칸을 고르기 불편하다(2026-11-15 안드로이드 실기기 확인). 터치 드래그를 늘 켜 두면 그리드 위에서 페이지 스크롤이 막히므로(R-19) 사용자가 켜고 끄는 선택 모드가 필요하다.

## 목표와 범위

- 이번에 구현할 동작:
  - 터치가 주 입력인 기기(`pointer: coarse`)에서만 그리드 위에 「드래그로 선택」 버튼(켜고 끄기)
  - 꺼짐(기본): 지금과 같음 — 끌면 스크롤, 누르면 한 칸
  - 켜짐: 그리드 칸 위에서 끌면 데스크톱과 같은 규칙(사각형, 첫 칸의 반대 상태)으로 선택, 누르면 한 칸. 손가락 아래 칸은 지금 손가락 좌표로 찾는다. 칸 영역만 스크롤을 막고, 날짜 머리글·시각 열·그리드 밖에서는 스크롤된다
  - 켜짐 표시(버튼 눌림, 그리드 파란 테두리)와 처음 켤 때 짧은 안내
  - 날짜 머리글 하루 토글, 지난 칸 회색·선택 불가, 읽기 전용(마감·확정)에서 버튼 숨김은 그대로
- 이번에 구현하지 않을 동작: 길게 누르기 방식, 끌다가 화면 끝에서 자동 스크롤, 두 손가락 스크롤, 마우스 데스크톱 변경, API·DB 변경

## 선행 작업

fix 002(`createDragTracker`, PR #2 병합). 구현을 막는 미결 규칙 없음.

## 사용자 흐름

내 가능 시간 그리드(입력 가능 상태, 터치 기기) → 「드래그로 선택」을 누름 → 버튼 눌림·그리드 파란 테두리·안내 1회 → 칸 위에서 끌어 여러 칸 선택(놓는 순간 확정, 제출 전 로컬 입력) → 다시 눌러 끄면 그리드 위에서 다시 스크롤. 마감·확정되면 버튼이 사라지고 선택 모드도 꺼진다.

## 수용 기준

- [x] AC-1 (R-38): 터치 기기에서만 「드래그로 선택」 버튼이 보이고(`aria-pressed`), 마우스 데스크톱·읽기 전용에서는 보이지 않는다
- [x] AC-2 (R-38, TIME-09-01): 켜면 칸 위에서 끈 손가락 위치의 칸까지 사각형으로, 첫 칸의 반대 상태로 선택된다(`createDragTracker`·`applyRect` 재사용). 지난 칸은 바뀌지 않는다
- [x] AC-3 (R-38): 꺼져 있으면 터치로 끌어도 칸이 바뀌지 않고 스크롤된다. 칸 영역의 `touch-action`은 켜졌을 때만 `none`
- [x] AC-4 (R-38): 켜졌을 때도 탭은 한 칸 토글(두 번 바뀌지 않음), 날짜 머리글 하루 토글은 그대로
- [x] AC-5 (R-38): 켜짐이 화면에 분명히 보이고(버튼 눌림·그리드 테두리), 처음 켤 때 안내를 한 번 보여 준다
- [ ] AC-6: 손가락 좌표 → 칸 판단은 순수 함수이고 단위 테스트가 있다
- [ ] AC-7: 기존 통합 테스트 세 프로젝트 회귀 없음, 모바일 터치 드래그 통합 테스트 추가, 단위·lint·typecheck·build, `TZ=UTC`·`America/Los_Angeles`
- [ ] AC-8: 미리보기 배포 `@smoke` 2회, MOBILE_CHECKLIST 안드로이드 실기기 항목 추가
