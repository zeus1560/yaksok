# 시간 입력 화면이 진행 중인 요청 결과를 받지 못하는 문제

## 환경과 증상

- 발견: 028 작업 중 027 확인 스크립트 회귀(2026-11-10, dev 서버, Playwright). `.next`를 지우고 새로 띄운 dev 서버에서 3회 중 2회 실패
- 기대: 재조율 뒤 방장·참여자 화면이 바로 시간 입력 화면으로 바뀌고 가능 시간이 채워진다
- 실제: 안내·방장 메뉴·명단은 바뀌었는데 시간 입력 영역만 "가능 시간을 불러오고 있어요…"에 머물다가 다음 폴링(5초)에 채워졌다(7.1초)

## 재현

1. 방장이 후보 화면에서 "모두의 시간 보기"를 연다(같은 `/availability` 주소를 5초마다 조회)
2. 그 조회가 진행 중이거나 막 끝난 때(1초 안)에 재조율이 끝나 시간 입력 화면이 새로 그려진다
3. 새 시간 입력 화면은 다음 주기까지 비어 있다. 실패 회차의 요청 순서: `/availability` 200(31852ms) → `/reopen` 200(32344ms) → `/availability` 200(32352ms) → 약 7초 동안 `/availability` 없음. 링크 재조회·`/me` 요청은 없었다

## 원인과 수정 범위

- 원인: SWR 2.5.1은 같은 주소 요청이 진행 중이거나 끝난 뒤 `dedupingInterval`(1초) 안이면 새로 그려진 화면을 그 요청에 합류시킨다. 합류한 화면은 `data`는 받지만 `onSuccess`는 요청을 시작한 화면에만 불린다(`node_modules/swr/dist/use-swr-emll9s78.mjs` 305·430행 `shouldStartNewRequest`). 화면 값을 `onSuccess`로만 채우던 곳은 합류하면 비어 있다
- 같은 방식의 SWR 사용처(전부):
  1. `components/availability/availability-board.tsx` 가능 시간(TIME-API-02) — 실제 발생. 입력·후보·결과 화면이 바뀔 때마다 새로 그려지고 "모두의 시간"과 같은 주소를 쓴다
  2. `components/result/promise-room.tsx` 상태 조회(STATE-API-01) — 참여 화면이 다시 그려질 때(재로그인 등 링크 재조회) 앞 화면의 요청에 합류할 수 있다
  3. `components/result/promise-room.tsx` 명단(MEMBER-API-06) — 2와 같다
- 수정: 세 곳 모두 SWR `data`로 받는다. `lib/availability/intake.ts` `createIntake`가 새 응답(다른 객체)마다 정확히 한 번만 넘기고(다시 그려지기만 하면 처리 없음), 화면이 생기기 전에 시작된 요청의 응답은 `joined`로 표시한다. 합류 창(3초) 밖의 오래된 캐시는 넘기지 않는다(SWR이 마운트 때 새로 조회)
  - 시간 입력 화면: `joined` 응답은 화면만 채우고(로컬 입력 판단 생략) 바로 새로 조회해 그 응답으로 버전 비교·범위 정리를 한다 — 재조율 직전에 시작한 "마감" 상태 응답으로 로컬 입력을 버리지 않게
  - 상태 조회: `joined` 응답은 반영하고 새로 조회한다. 버전·마감 판단(`decidePoll`)은 응답마다 한 번
  - 명단: 화면 값(명단·불안정 표시)은 렌더 중 "이전 data와 비교해 상태 조정"으로 반영하고, 링크 재조회·새로 조회는 효과에서 응답마다 한 번(`react-hooks/set-state-in-effect` 규칙)
  - `Timed.finishedAt` → `receivedAt`(intake와 같은 이름)
- 보존: 폴링 간격·탭 숨김 정지·실패 시 마지막 값 유지, 드래그 중 보류·제출 중 건너뜀·제출 뒤 낡은 응답 버림, 다른 기기 변경 안내·로컬 입력 유지·409 충돌 처리(012)
