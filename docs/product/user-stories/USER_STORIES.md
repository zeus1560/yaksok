## 백로그 운영 기준

2026-09-18 사용자 결정 반영. User Story는 사용자 목표, Rules & Acceptance Criteria는 완료 조건, Task는 실제 구현·기술 검증 작업으로 관리한다.

- 활성 User Story: MVP 16개 / 후속 16개.
- 중복된 기존 스토리 4개는 통합 대상으로 연결하고 이전 기록에 보존했다.
- 이전 하위 AC는 현재 스토리 본문으로 재작성했다. 예전 문장은 이전 기록에서만 참고한다.
- 기본 릴리스 기준은 **릴리스** 속성이다. **MVP (이전 분류)** 는 변경 전 기록이다.
- **기획 상태**는 개발 준비 상태, **상태**는 실제 개발 진행 상태다. 기획 정리만으로 개발 완료 처리하지 않는다.

### 보기 사용법

- MVP: 이번 릴리스의 사용자 목표.
- 전체 / 후속: 모든 활성 스토리와 이후 릴리스 범위.
- 결정 필요: 제품 정책 또는 기술 검증이 남은 스토리.
- 개발 진행 / 개발 Task: 실제 구현 상태와 기술 검증 작업.
- 이전 기록: 통합된 스토리와 이전 AC·메모. 현재 구현 기준으로 사용하지 않는다.

사용자가 바꾼 답변을 우선하고 나머지 추천안은 채택했다. 답변의 49번 공유 문장은 질문 52번에 반영했으며 질문 49번 최다 득표·동률 정책은 추천안을 유지했다.

### US-CREAT-03 — 초대 링크 접속 ❗미결
- **릴리스**: MVP / **기획 상태**: 결정 필요 / **상태**: 시작 전
- **우선순위**: P0 / **기능영역**: 약속생성
- **사용자 목표**: 참여자로서 초대 링크로 약속에 접속하여 조율에 참여하고 싶다.
- **완료 조건 (Acceptance Criteria)**:
  - [ ] 유효하지 않거나 폐기된 초대 링크는 참여를 허용하지 않고 안내한다.
  - [ ] 최종 확정 후 신규 참여 정책(Q16)은 보류이며 허용·차단 어느 쪽도 확정된 정책으로 구현하지 않는다.
  - 초대 링크 재공유
    - [ ] 초대 링크를 가진 사람은 참여할 수 있으며 다른 톡방으로 전달된 링크도 같은 정책을 적용한다. 생성 화면에서 링크 소지자 참여 가능 사실을 안내한다.
  - 참여 전 정보 공개
    - [ ] 참여 등록 전에는 약속 이름·진행 상태만 공개한다. 참여자의 상세 응답은 등록 후 권한에 따라 조회한다. 결과 공유 링크는 별도 공개 범위를 적용한다.
  - 초대 링크 만료와 재발급
    - [ ] MVP는 초대 링크를 자동 만료시키지 않는다. 방장은 초대 링크를 폐기·재발급할 수 있고 재발급하면 이전 초대 링크로 신규 참여할 수 없다. 취소된 약속은 신규 참여를 차단한다. 데이터 보존 기간이 끝난 약속은 링크로 복원하지 않는다.
  - 결과 링크와 초대 링크 구분
    - [ ] 결과 링크는 조회용이고 신규 참여는 초대 링크로 진행한다. 결과 공유와 참여 초대의 목적을 구분한다.

### US-CREAT-04 — 약속 생성 및 초대 링크 발급
- **릴리스**: MVP / **기획 상태**: 개발 가능 / **상태**: 시작 전
- **우선순위**: P1 / **기능영역**: 약속생성
- **사용자 목표**: 방장으로서 약속을 만들고 초대 링크를 공유하여 함께 일정과 장소를 정하고 싶다.
- **완료 조건 (Acceptance Criteria)**:
  - [ ] 필수 입력이 유효하면 약속·방장 참여 자격·고유 초대 링크가 함께 생성된다.
  - [ ] 설명이 없고 장소·확정 시간이 미정이어도 약속을 생성할 수 있다.
  - 방장 지정 기준
    - [ ] 약속 생성자를 방장으로 지정하며 생성 과정에서 참여자로 함께 등록한다. 링크에 처음 접속한 사람을 방장으로 지정하지 않는다.
  - 약속 생성 필수 입력
    - [ ] 약속 이름·방장 닉네임·조율 날짜 범위를 필수로 받는다. 날짜 범위는 오늘부터 기본 3개월이다. 설명은 선택이며 장소·확정 시간은 나중에 입력한다.
  - 날짜와 장소 조율 순서
    - [ ] 날짜·장소는 모두 언제든 입력할 수 있다. MVP에서는 순서 선택을 생략하며, 어느 한쪽의 확정이 다른 쪽 입력의 선행 조건이 되지 않는다.
  - 참여 인원과 최소 확정 인원
    - [ ] 참여 인원에 제품상 최대 제한을 두지 않는다. 생성·입력은 혼자서도 가능하며 일정 확정에는 참여 가능 인원 2명 이상이 필요하다.
  - 초대 링크 재공유
    - [ ] 초대 링크를 가진 사람은 참여할 수 있으며 다른 톡방으로 전달된 링크도 같은 정책을 적용한다. 생성 화면에서 링크 소지자 참여 가능 사실을 안내한다.
  - 초대 링크 만료와 재발급
    - [ ] MVP는 초대 링크를 자동 만료시키지 않는다. 방장은 초대 링크를 폐기·재발급할 수 있고 재발급하면 이전 초대 링크로 신규 참여할 수 없다. 취소된 약속은 신규 참여를 차단한다. 데이터 보존 기간이 끝난 약속은 링크로 복원하지 않는다.
  - 닉네임 규칙
    - [ ] 닉네임은 앞뒤 공백 제거 후 1~12자이며 한글·영문·숫자·공백을 허용한다. 공백만 입력한 값은 허용하지 않는다. 동일 약속 안에서 중복 닉네임을 허용하지 않는다.
  - 미응답자 자동 퇴장
    - [ ] 자동 퇴장·개인 응답 타임아웃은 MVP에서 제외한다. 미응답으로 표시하고 방장이 필요할 때 제외한다. 장소 투표 마감시간은 별도 정책이다.
  - 조율 날짜 기본값과 최대 범위
    - [ ] 한국 시간 기준 오늘부터 기본 3개월을 제공한다. 방장이 조율할 날짜 범위의 상한·종료일을 선택할 수 있다. 과거 날짜 선택은 허용하지 않는다. 기본 3개월을 서비스의 고정 최대 범위로 취급하지 않는다.
  - 약속 예상 소요시간
    - [ ] 방장이 예상 소요시간을 설정하며 기본 1시간이다. 소요시간만큼 연속으로 가능한 구간을 추천한다.

### US-AUTH-04 — 참여 취소 및 참여자 제외
- **릴리스**: MVP / **기획 상태**: 개발 가능 / **상태**: 시작 전
- **우선순위**: P1 / **기능영역**: 참여자등록
- **사용자 목표**: 참여자 또는 방장으로서 참여를 취소하거나 이탈한 참여자를 제외하여 실제 인원으로 조율하고 싶다.
- **완료 조건 (Acceptance Criteria)**:
  - [ ] 본인은 자신의 참여만 취소할 수 있고, 방장만 다른 참여자를 강제 제외할 수 있다.
  - [ ] 참여 기록은 취소·제외 상태로 남기며 진행 중 집계에서는 해당 응답·표를 제외한다.
  - 비회원 방장과 권한 위임
    - [ ] 비회원 방장을 허용하고 다른 참여자에게 방장 권한을 위임할 수 있다. 다른 참여자가 남아 있으면 위임 후 나갈 수 있다.
  - 참여 취소와 강제 제외

- **우선순위**: P1 / **기능영역**: 장소선정
- **사용자 목표**: 참여자로서 원하는 장소를 후보로 추가하고 관리하여 추천 외의 의견도 투표에 반영하고 싶다.
- **완료 조건 (Acceptance Criteria)**:
  - [ ] 검색한 장소를 후보로 추가하면 전체 후보 목록에 표시한다.
  - [ ] 전체 후보 목록에는 이름·주소·지도 링크를 표시한다.
  - [ ] 동일 장소 추가 요청은 기존 후보를 안내하며 중복 후보를 만들지 않는다.
  - 장소 정보 MVP 범위
    - [ ] MVP 장소 정보는 이름·주소·지도 링크 중심으로 제공한다. 이동시간 비교와 사진·영업시간 등 상세 정보는 후속 릴리스로 분리한다.
  - 추천 결과 없음·검색 실패
    - [ ] 반경을 넓혀 다시 검색하거나 직접 후보를 추가할 수 있다. 검색 실패 시 기존 후보는 유지한다.
  - 장소 후보 관리
    - [ ] 참여자는 모두 후보를 추가할 수 있다. 전체 후보 개수에 제품상 최대 제한을 두지 않고 동일 장소는 중복 추가할 수 없다. 본인은 투표 시작 전 본인 후보를 삭제할 수 있으며 방장은 전체 후보를 관리한다.
  - 득표 후보 삭제와 확정 후 수정
    - [ ] 장소 확정 전에는 방장이 득표 후보를 삭제할 수 있고 해당 표가 취소됨을 안내한다. 장소 확정 후에는 재조율을 시작해야 후보·투표를 수정할 수 있다.

### US-PLACE-06 — 출발지 기반 중간 지점 조회
- **릴리스**: 후속 / **기획 상태**: 개발 가능 / **상태**: 시작 전
- **우선순위**: P1 / **기능영역**: 장소선정
- **사용자 목표**: 참여자로서 출발지의 중간 지점을 확인하여 만날 지역을 파악하고 싶다.
- **완료 조건 (Acceptance Criteria)**:
  - [ ] 출발지 등록·변경 또는 유효 참여자 변경 후 입력된 좌표로 중간 지점을 갱신한다.
  - [ ] 중간 지점이 실제 만남에 부적절한 위치여도 좌표를 왜곡하지 않고 주변 장소 추천·수동 후보 추가로 이어갈 수 있다.
  - 출발지 입력과 미입력자
    - [ ] 역·장소·주소를 검색해 출발지를 선택한다. 출발지는 참여 필수 조건이 아니다. 장소 추천에는 입력된 출발지만 사용하며 미입력 인원을 표시한다.
  - 중간 지점 산출 기준
    - [ ] MVP는 입력된 출발 좌표 평균을 중간 지점으로 계산한다. 이동시간이 공평한 지점이라고 표현하지 않는다.
  - 출발지·참여자 변경과 후보 유지
    - [ ] 중간 지점은 갱신하되 투표 중인 후보는 유지한다. 방장이 새 추천 적용을 선택하면 기존 투표가 초기화된다는 안내 후 적용한다. 이미 확정된 장소는 재조율 전까지 유지한다.
