# 완료 기록

1. 스펙의 수용 기준과 최신 검증 결과를 확인한다. 필요한 검증이 실패하거나 미실행이면 완료로 표시하지 않고 남은 작업을 기록한다.
2. 통과한 경우 상태를 `완료`로 바꾸고 연결된 스펙에도 결과를 남긴다.
3. 완료 이력 맨 아래에 날짜, 기능명, 스펙 경로, 브랜치, 변경 요약, 실제 검증 근거를 추가한다. 같은 완료를 반복 요청하면 중복 기록하지 않는다.
4. `context/feature-list.md`의 상태를 맞춘다.
5. 커밋·푸시를 요청받았다면 현재 브랜치가 이 기능의 `<이름>/<타입>-<설명>` 브랜치인지 확인하고 이 기능의 파일만 커밋해 `origin`(개인 저장소)의 같은 이름 브랜치로 푸시한다(`git push -u origin <브랜치>`). `team`(팀 저장소)에는 푸시하지 않는다. `main`에는 푸시하지 않는다. 스키마 변경이 있으면 `prisma/migrations/`의 새 폴더를 포함한다. PR 생성·병합·배포는 하지 않고, 푸시 후 PR을 만들라고 안내한다. 병합 후에는 `main`으로 돌아가 `git pull`하고 다음 기능 브랜치를 새로 만들라고 안내한다.

최종 답변에는 완료한 결과, 검증, 남은 제한을 간결하게 적는다. 검증하지 않은 배포나 DB 연결을 완료로 보고하지 않는다.
