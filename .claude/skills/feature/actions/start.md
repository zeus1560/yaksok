# 구현 시작

현재 기능과 연결된 스펙을 읽는다. 목표가 비어 있으면 기능을 먼저 불러오도록 안내한다. 구현을 막는 미결 규칙이 있으면 알리고 그에 의존하는 구현을 시작하지 않는다. 이미 확정된 범위는 반복 확인하지 않는다.

1. `git status`, 현재 브랜치, HEAD를 확인하고 작업 기준점에 기록한다.
2. 이미 이 기능의 브랜치(`<이름>/feat-...` 등)에 있으면 그대로 진행한다. 그 외의 브랜치(`main`, 다른 기능 브랜치, 접두어 없는 개인 브랜치)에 있으면 작업 트리가 깨끗한지 확인하고 `main`으로 이동해 `git pull` 후 `<이름>/feat-<스펙ID>` 브랜치를 만든다(수정 기록이면 `fix-`). 이름 접두어를 모르면 묻는다. 미커밋 변경이 있으면 브랜치를 바꾸지 말고 이유를 알린다.
3. 상태를 `진행 중`으로 바꾸고 수용 기준을 만족하는 최소 변경을 구현한다. 소스는 루트의 `app/`, `components/`, `lib/` 등에, 스펙과 기록은 `context/`에 둔다.
4. 스키마를 바꾸면 본인 Neon 개발 DB에 `npm run db:migrate -- --name <변경명>`으로 마이그레이션을 만들고 `npm run db:generate`를 실행한다.
5. 구현 중 요구사항이 달라지면 스펙도 동기화한다. 규칙 문서와 다르게 구현해야 할 것 같으면 멈추고 확인한다.
6. 변경 파일, 실행한 검증, 아직 충족하지 못한 기준을 기록한다.

커밋·푸시는 별도 요청 범위를 따른다.
