# 검증

현재 기능의 수용 기준과 변경 파일을 읽고 검증을 연결한다.

- 입력·권한 검증, 상태 전이, 시간·후보 계산, 경계 조건에 의미 있는 로직이 있으면 Vitest 테스트를 작성하거나 수정한다. 성공뿐 아니라 오류·권한 없는 요청·잘못된 상태도 확인한다. DATABASE.md 11절 체크리스트 중 해당 사례를 테스트로 옮긴다.
- 단순 CSS나 정적 화면에 구현을 반복하는 테스트를 만들지 않는다.
- 테스트가 있으면 `npm run test`를 실행한다. 없으면 `테스트 없음`을 기록한다. 빈 테스트를 통과시키려고 설정을 바꾸지 않는다.
- `npm run lint`, `npm run typecheck`, `npm run build`를 실행한다.
- DB 변경이 있으면 `npm run db:status`로 본인 개발 DB의 마이그레이션 상태를 확인한다. 운영 DB로 테스트하지 않는다.
- UI 변경이 있으면 브라우저에서 수용 기준의 흐름과 모바일 화면을 확인한다. 사용할 수 없는 도구는 제한으로 기록한다.

## dev 서버와 확인 스크립트

- `npm run build`는 dev 서버를 끈 상태에서만 실행한다. 같은 `.next` 폴더를 써서 실행 중인 dev 서버가 500을 낸다.
- 작업이 끝나면 확인용으로 띄운 dev 서버를 모두 종료한다. 백그라운드 작업만 멈추면 하위 `next` 프로세스가 남을 수 있으니 포트·프로세스가 비었는지 확인한다.
- 확인 스크립트는 세션 쿠키·토큰 값을 출력하지 않는다. 필요하면 앞 몇 글자만 표시한다.

명령은 저장소 루트에서 Node.js 24로 실행한다. `context/current-feature.md`에 명령, 결과, 수용 기준, 미실행 이유를 남긴다. 실패를 고치면 영향을 받는 검증을 다시 실행한다.
